# Deploying

The package is published to npm as `@tallio/contentful-mock`. Only the `dist/` folder is included (see `files` in `package.json`).

## Automated releases

Releases are automated with [semantic-release](https://semantic-release.gitbook.io). Every merge (push) to `master` runs `.github/workflows/release.yml`, which lints, tests and builds, then inspects the Conventional Commit messages since the last release:

- `fix:` → patch, `feat:` → minor, `!` / `BREAKING CHANGE` → major.
- Only `chore:`, `docs:`, `test:` etc. → no release.

When a release is due it updates `CHANGELOG.md` and `package.json`, publishes to npm (with provenance), commits `chore(release): x.y.z [skip ci]`, tags `vX.Y.Z` and creates a GitHub release.

Preview what the next release would be locally with `npm run release:dry`.

## One-time setup

- Add an npm token with publish rights as the repository secret `NPM_TOKEN`.
- Branch protection on `master`: require a pull request and the status checks `Lint, test, build (Node 18/20/22)` and `Commit messages` (from `ci.yml`) before merging. If you also block direct pushes, allow `github-actions[bot]` (or a bypass role) so the release can push its version commit.

## Pull request checks

`.github/workflows/ci.yml` runs lint, tests, build and a commit message check on every PR.

## Notes

- The version in `package.json` is managed by semantic-release; don't bump it by hand.
- `dist/` is generated by `npm run build` and must be built before publishing (the workflow does this).
- `contentful` and `contentful-management` are optional peer dependencies; they are not bundled.
- The `examples/` directory is not published.
